# DataEase 前端设计规范化计划

## 审查结果摘要

| 类别 | 问题数 | 涉及文件 |
|------|--------|----------|
| 非标准字号 | 50+ | 30+ |
| 非标准字重 | 12 | 10 |
| 硬编码颜色 | 200+ | 68+ |
| 非标准边框色 | 20+ | 20 |
| 非标准圆角 | 50+ | 25 |
| 不一致阴影 | 40+ | 40 |

## 修复计划（按优先级排序）

### 阶段一：建立设计令牌基础（影响最大，风险最低）

- [x] **1.1** 在 `variable.less` 中补充缺失的设计令牌（暗色头部背景、边框色、阴影、圆角等）
- [x] **1.2** 将设计中实际使用的字号纳入规范（16px、18px 作为补充层级，而非违规）
- [x] **1.3** 统一危险色 `#f56c6c` → `#F54A45`（5个文件）
- [x] **1.4** 统一背景色 `#f5f7fa` → `#F5F6F7`（15 个文件）

### 阶段二：圆角和边框色统一

- [x] **2.1** 统一 `border-radius: 3px` → `4px`（44 处，22 个文件）
- [x] **2.2** 统一边框色：`#bbbfc4`、`#d9d9d9`、`#e4e7ed`、`#e6e6e6`、`#dcdfe6` → `#DEE0E3`（~70 处，~40 个文件）

### 阶段三：阴影标准化

- [x] **3.1** 在 `variable.less` 中定义 3 个标准阴影令牌（标准/中等/轻微）
- [x] **3.2** 统一阴影格式：hex 写法 → rgba 写法，统一 `0px 5px 10px` → `0px 4px 12px`（9 个文件）

### 阶段四：字重和内联样式清理

- [x] **4.1** `font-weight: 600` / `bold` → `500`（11 处，跳过 ComponentFrame.vue 功能性标记）
- [x] **4.2** `color: red` → `#F54A45`（2 处），`#909399` → `#8F959E`（15 处，13 个文件）

### 阶段五（可选）：暗色模式令牌化

- [ ] **5.1** 将画布编辑器中的硬编码暗色值提取为 CSS 变量
- [ ] **5.2** 修复 `body { background: #ffffff }` 硬编码

---

## 不做的事情

- **不批量修改字号**：16px、18px 等已被广泛使用，实际需要用于视觉层次，应纳入规范而非删除
- **不修改画布编辑器的暗色主题色**：这是独立的设计区域，有自己的视觉规范
- **不替换原生 `<button>` 为 `ed-button`**：这些是功能性差异，不是样式问题
- **不添加新的 CSS 框架或设计系统库**

---

## 审查总结

### 修改统计
- **修改文件数**: ~65 个 .vue 文件 + 2 个 .less 文件
- **总替换数**: ~200+ 处
- **新增令牌**: `variable.less` 新增 20 个设计令牌

### 主要改动

1. **设计令牌基础** (`variable.less`): 新增颜色、阴影、圆角、字号令牌，为后续开发提供统一参考
2. **危险色统一**: `#f56c6c` → `#F54A45`，涉及 login、permissions 等页面
3. **背景色统一**: `#f5f7fa` → `#F5F6F7`，涉及 15 个文件（permissions 目录为主）
4. **圆角统一**: `3px` → `4px`，涉及 22 个文件的 dialog/面板组件
5. **边框色统一**: 5 种不同灰色 → `#DEE0E3`，涉及 ~40 个文件
6. **阴影格式统一**: hex 写法 → rgba 写法，统一间距参数
7. **字重统一**: `600`/`bold` → `500`
8. **提示色统一**: `#909399` → `#8F959E`

### 保留不动的
- `#bbbfc4` 在 disabled 按钮/文字上下文中保留（语义性用法）
- `font-weight: bold; color: lawngreen` 在 ComponentFrame.vue 保留（功能性调试标记）
- 画布编辑器的暗色主题硬编码色保留
- 16px、18px 等非标准字号保留（实际需要用于视觉层次）
